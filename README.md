# 宠物蜜蜂 Pet Bees 1.0.4

适用 Minecraft **26.2**、Fabric Loader **0.19.3 或更新版本**、Java **25**。
需要 Fabric API **0.158.0+26.2 或对应 26.2 的更新版**。

## 安装

将 `petbees-1.0.4+26.2.jar` 同时放入服务器和所有玩家客户端的 `mods` 文件夹，替换旧版后重启游戏与服务器。不要同时保留两个版本。
Jade 信息显示需要客户端和服务器安装 Jade；本次对应版本为 **26.2.11**。没有 Jade 时，其余功能仍可使用。

无需创建新世界。模组直接扩展原版蜜蜂、蜂巢和蜂箱。

1.0.1 修复了 Jade 客户端拒绝注册旧版混合数据／提示框提供者的问题。现在分别注册服务端数据提供者和客户端提示框提供者。已有蜜蜂的认主数据不变，不需要重新驯服。

1.0.2 增加蜂箱／蜂巢的“未驯服蜜蜂”数量，同时显示已驯服数量（包括数量为 0 的情况），保留主人列表。实体未驯服时也明确显示“未驯服”；数据包尚未到达时不把未知状态误判为未驯服。

认主保护：不完整的 NBT 重载不再清空已知主人的蜜蜂状态；使用 Fabric 原生持久化附件独立备份主人 UUID 和名字。旧版有效记录在加载／保存时自动建立备份，原有主数据格式保留。主记录缺失而备份有效时自动恢复。更新前已经丢失且没有备份的记录无法自动还原，也不会把野生蜜蜂擅自分配给附近玩家。

本次尚未复现用户现场报告的“攻击后脱驯”，加固措施不代表根因已经证实。新版在服务端日志记录 `[PetBees ownership]`（保护／恢复认主）和 `[PetBees death]`（宠物死亡，含坐标与主人）。若再发生，保留当时的 `logs/latest.log` 及异常蜜蜂所在存档，以便进一步确认是数据重载、死亡或其他路径。

## 1.0.4 更新

- 计数核验服务器实际实体注册表和当前区块里的蜂箱对象，过滤失效索引；仍不强制加载区块。
- 原 count/watch 明确显示“全维度已加载”，保留原统计范围。增加 `/petbees count nearby` 和 `/petbees watch nearby`，只统计自己所在维度、距离自己 32 格内的蜜蜂及蜂巢／蜂箱。附近模式包含幼蜂，以蜂箱中心判定巢内蜜蜂距离，随玩家移动而变化；使用每秒一次共享快照。
- 在自然出巢、交蜜和紧急出巢实际加入世界前，依据本次出巢的确切巢内记录核验认主。如记录有主人而实体丢失主人，恢复并写入 `[PetBees ownership]` 日志。不会根据旁边玩家或同巢其他蜜蜂推断主人。
- 提供的存档中确有大量远处的已驯服巢外蜜蜂；“白天脱驯”尚未复现，不能将上述保护等同于已确认并修复现场根因。已丢失且无任何有效主人记录的蜜蜂无法自动恢复。

## 个人蜜蜂数量调试

普通玩家可直接使用，无需 OP：

- `/petbees count`：查询属于自己的已驯服蜜蜂总数，并分别列出在外数量、蜂巢／蜂箱内数量。
- `/petbees watch`：开启实时显示，每 20 个游戏 tick（正常速度约 1 秒）在快捷栏上方刷新，同时显示相对上次刷新的数量变化。
- `/petbees watch off`：关闭显示。退出服务器也会关闭，下次上线可重新开启。

包含成年蜜蜂和幼蜂，依据主人的 UUID 统计，排除死亡蜜蜂、野生蜜蜂和其他玩家的蜜蜂。覆盖所有维度中已加载的蜜蜂、蜂巢和蜂箱。

**这是已加载数量，不是全部存档中的总数。** 不强制加载区块，不读取未加载区域，不包含物品栏、箱子、掉落物中的蜂箱物品内的蜜蜂。因此离开蜂场导致区块卸载、收走蜂箱等也会使数量减少，不能仅凭减少判定死亡或脱驯。单次查询最多使用约 1 秒前的共享快照。

性能：使用 Fabric 实体／方块实体加载和卸载事件，仅索引蜜蜂、蜂箱、蜂巢；只在有监测者或执行查询时统计，不扫描全部实体和区块。多名玩家共享每秒一次的计数结果。

## 蜜蜂小食

使用提供的原始贴图。两种配方均为无序合成，并返还所有空玻璃瓶：

- 蜜脾 ×1 + 蜂蜜瓶 ×1 → 蜜蜂小食 ×1。
- 蜂蜜块 ×1 + 蜂蜜瓶 ×4 → 蜜蜂小食 ×4。

创造模式可在原材料栏找到，也可执行 `/give @s petbees:bee_snack 64`。

## 驯服、治疗和繁殖

- 手持小食右键野生蜜蜂。每位玩家对每只蜜蜂分别累计次数，前两次各有 30% 成功率，第三次必定成功；成功者成为主人。
- 幼蜂也能驯服，成年后才参与战斗。成功出现爱心，失败出现烟粒子。
- 任意玩家都能用一份小食将宠物蜜蜂治疗至满血，并解除尚未结算的蜇刺损伤。满血且没有待结算损伤时不消耗小食。
- 花仍用于原版繁殖。单方驯服时后代继承该方主人；双亲主人相同时继承共同主人；双亲主人不同时归最后喂花促成求偶的玩家。
- 认主 UUID、主人名字、驯服次数及待结算损伤随实体保存，也会保留在蜂箱及带蜜蜂的蜂箱物品中。
- Jade 显示蜜蜂的驯服状态和主人名字，也显示蜂箱／蜂巢内已驯服、未驯服数量及宠物主人。离线模式服务器直接使用游戏内记录的名字，不查询外部账号服务。

## 护主与撤退

- 宠物不跟随主人，平时继续原版采蜜、授粉、回巢等行为。
- 主人受到实体攻击或成功攻击实体时，召集主人 32 格球形范围内的成年宠物，以及这个范围内已加载蜂巢／蜂箱中的成年宠物。
- 怪物、玩家、其他玩家的宠物均可作为敌人。环境伤害没有攻击者，不召集蜜蜂。主人攻击自己的蜜蜂也不触发围攻。
- 夜间和下雨也能出巢。混住的野生蜜蜂、其他主人的蜜蜂和幼蜂不会随之出动。
- 以每只蜜蜂本次出动地点为中心，蜜蜂、敌人或主人超出 32 格便撤退；主人死亡、离线或跨维度也撤退。
- 敌人死亡后可接着攻击附近正在攻击主人的其他敌人，切换目标不重置出动地点或扣血次数。
- 从蜂箱出动的返回原箱，在外出动的返回出动地点附近，然后继续原版生活。原箱被拆除、已满或附近有火时恢复普通寻巢行为；不可达路线有超时退出，避免永久卡在自定义任务。

## 蜇刺扣血

- 攻击非玩家实体不扣血。
- 一次出动中可以多次蜇刺，只有首次成功蜇伤玩家才记录一次待结算损伤。
- 保留原版每 5 tick 随机检查、最迟约 1200 tick（正常速度约 60 秒）的延迟结算机制，最终扣血改为 5 点。
- 当前血量大于 5 时减 5；大于 1 且不超过 5 时留 1；当前血量不超过 1 时死亡。典型过程：10 → 5 → 1 → 死亡。
- 蜜蜂在蜂箱内或区块未加载时不运行实体 AI，延迟计时暂停；出巢／重新加载后继续。待结算记录不会因进出蜂箱或重启而清空。
- 主人误伤仍造成正常伤害，但自己的蜜蜂不反击。主人采蜜或剪蜜脾时，自己的蜜蜂短暂出巢后回巢，野生及其他主人的蜜蜂保留各自反应。

## 性能与构建

护主查询由实际战斗事件触发，同一玩家同一 tick 合并为一次；仅查询附近蜜蜂和已加载区块的方块实体，不遍历全世界、不强制加载区块。
平时没有周期性范围扫描。撤退寻路使用原版飞行导航，每隔若干 tick 更新一次。

源码位于本文件所在目录。安装 JDK 25 后，Windows 执行 `gradlew.bat build`，构建产物位于 `build/libs`。
编译 Jade 接口使用 `libs/jade.jar`。游戏测试源码单独放在 `src/gametest`，不会装入交付 JAR。
兼容性测试使用 `gradlew.bat build -Pcompat`，将 `compat-mods` 中本地的 Jade、Lithium、Carpet 和 Gugle Carpet Addition 加入测试服务器。
